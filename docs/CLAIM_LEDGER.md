# Claim Ledger

Use this ledger to keep agents honest about what the repo actually knows. A
claim is not prize-facing just because it has a large run behind it.

## Levels

| Level | Meaning | Merge standard |
|---|---|---|
| Observation | One experiment or exploratory score. | Record setup, command, result, and next check. |
| Robust observation | Controls/nulls and at least one robustness check. | Include verification, baselines, and failure mode. |
| Certificate | Finite artifact another agent can verify. | Include verifier command and artifact path. |
| Theorem | Proved outright, no experiment needed. | Include the proof or a one-line derivation. |
| Proof candidate | Theorem-shaped argument with checkable lemmas. | Include assumptions, proof gaps, and reproduction path. |
| **Retracted** | Was recorded at a higher level and should not have been. | State what was wrong and what replaces it. |

## Admission Rule (added 2026-08-15)

Before a negative result ("we searched class `M` and found no fit") is recorded
at any level, state `log2|M|` and the prefix length `n`. If `log2|M| < n` the
result is **vacuous by counting** and must not be recorded as a Certificate — any
sequence whatsoever produces it. See
[`docs/theory/finite-prefix-counting-bound.md`](theory/finite-prefix-counting-bound.md)
and `python experiments/counting_bound.py --pretty`.

A matching negative from the random control is a **red flag that the experiment
is vacuous**, not a reassuring baseline.

## Promotion Rule

When adding a new result, state the next promotion step explicitly. If there is
no plausible promotion path, the experiment is probably not worth expanding.
