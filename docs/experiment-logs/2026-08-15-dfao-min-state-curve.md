## Goal

Replace the repo's vacuous "no small DFAO fits 128 center bits" certificate with
a measurement that can actually distinguish Rule 30 from noise: the
**minimal-DFAO-size curve**

    s*(n) = min { s : some s-state binary-output DFAO reproduces center bits 0..n-1 }

measured against a random control and a genuinely automatic positive control.

## Why the previous certificate was vacuous

`docs/CLAIM_LEDGER.md` currently records as a Certificate:

> The first 128 center-column bits are not generated by any 1-4 state binary
> DFAO in MSD or LSD digit order.

and `docs/experiment-logs/2026-06-15-prize-frontier.md` extends this to 1-5
states. **Both statements are implied by counting alone and say nothing about
Rule 30.**

The argument is `docs/theory/finite-prefix-counting-bound.md`, implemented in
`experiments/counting_bound.py`. A binary-output DFAO with `s` states over
base-`b` digits and a fixed initial state is described by `s^(s*b)` transition
tables and `2^s` output labelings, so

    |M(s,b)| <= s^(s*b) * 2^s                  (UPPER bound)
    |M(s,b)| >= s^(s*b) * 2^s / (s-1)!         (LOWER bound)

The `(s-1)!` quotient by relabelings of the non-initial states gives a *lower*
bound, not an upper one (Burnside: #orbits >= |X|/|G|). The two uses need
opposite bounds: **vacuity verdicts use the upper bound** (overstating `|M|`
makes the vacuity claim conservative), **fair thresholds use the lower bound**.

Each fixed DFAO matches a uniformly random length-`n` binary string with
probability `2^-n`, so by the union bound

    P[some s-state DFAO fits n random bits] <= |M(s,b)| / 2^n .

A "no DFAO fits" result is informative only when `log2|M(s,b)| >= n`. For base 2,
upper bound:

| s | log2\|M\| | s | log2\|M\| | s | log2\|M\| |
|---|---|---|---|---|---|
| 4 | 20.0 | 10 | 76.4 | 16 | 144.0 |
| 5 | 28.2 | 11 | 87.1 | 17 | 156.0 |
| 6 | 37.0 | 12 | 98.0 | 18 | 168.1 |
| 7 | 46.3 | 13 | 109.2 | 19 | 180.4 |
| 8 | 56.0 | 14 | 120.6 | 20 | 192.9 |
| 9 | 66.1 | 15 | 132.2 | | |

At `n = 128` the 5-state class has `log2|M| = 28.2`, so the expected number of
5-state DFAOs fitting 128 random bits is at most `2^(28.2 - 128) = 2^-99.8`.
**Any** 128-bit sequence returns that same negative. The repo's own seeded-random
baseline produced the identical result, which is the empirical confirmation, and
it was logged as "expected" rather than as a refutation of the design. Pushing to
states 6-8 at n=128, which the frontier log planned, is still vacuous by `2^-72`.

The fair-test threshold at `n = 128` is `s >= 15` (optimistic) to `20`
(conservative) — an exhaustive space of at least `2^132`. That is why the
frontier had to be re-aimed: the informative question is not "does a tiny DFAO
fit a long prefix" (never) but "how does the *minimum* DFAO size grow with
prefix length, relative to a random string".

## Setup

- Tool: `experiments/dfao_min_states.py` (new)
- Sequence generation and CNF encoding reused unchanged from `prize_lab.py`
  (`sequence_bits`, `center_bits_int`, `dfao_sat_cnf`, `run_dfao`,
  `verify_candidate_on_bits`, `exhaustive_dfao_search`).
- Solver: in-process `pysat` CaDiCaL 1.5.3 (`Cadical153`), pysat PYSAT_VERSION.
  The repo previously had only an external `--solver-cmd` path and no solver
  binary on this machine.
- Base 2, digit directions MSD and LSD, initial state fixed to 0.
- Prefix lengths n = 8, 12, 16, 20, 24, 28, 32, 40, 48, 56, 64 (index 0 included).
- Per-instance timeout 120 s; a timeout is recorded as `UNKNOWN`, never as UNSAT.
- Controls:
  - **Positive**: Thue-Morse (genuinely 2-automatic) - must return s* = 2 at
    every n, in both digit directions, or the method cannot detect a real
    shortcut and the whole experiment is void.
  - **Null**: seeded random, seed 30, same budget - the empirical form of the
    counting null.
  - **Analytic null**: smallest s with `log2 N_eff(s,2) >= n`.

## Method

1. Build the DIMACS from `prize_lab.dfao_sat_cnf(bits, states=s, base=2, direction=d)`.
   That encoding carries a `c var <id> <name>` symbol table, so the model can be
   decoded back into a DFAO without re-deriving the encoding.
2. Solve in process with CaDiCaL under a wall-clock interrupt.
3. On SAT, decode `t_state{a}_digit{d}_state{dst}` and `out_state{s}` into a
   candidate and **re-run it through `run_dfao` / `verify_candidate_on_bits`**.
   A decoded automaton that does not reproduce its own bits raises immediately.
4. s*(n) = the first s (incrementing from 1) with a SAT verdict.

## Interpretation

**No DFAO shortcut, and this time the negative is not vacuous.**

The retracted claim asked "does a tiny DFAO fit a long prefix?" - guaranteed no,
by counting, for any sequence whatsoever. This asks instead how the *minimum*
DFAO size grows with prefix length, and compares that curve against a matched
random control. That is the quantity `docs/theory/finite-prefix-counting-bound.md`
identifies as the informative one, and it is the same design as Experiment S
(`L(n) = n/2`), which the theory doc calls the template for a sound negative.

Three things have to hold together for this to mean anything, and all three do:

1. **Detection power.** Thue-Morse returns `s* = 2` flat, at every n, in both
   directions. A real automatic sequence is found immediately.
2. **The measurement is in the informative regime.** Measured minima (10 at
   n=32) sit above the counting-null threshold (6-7 at n=32), so these are
   genuine minima rather than an artefact of the class being too small to fit
   anything.
3. **The center column is not special.** Its `s*(n)` lands inside the 7-seed
   random band at 9 of 9 exact points and never below. Where it deviates it
   deviates *upward* (n=24: 8 vs a band median of 8; n=8: 3 vs a seed-30 value
   of 2).

Note the Admission Rule's warning that "a matching negative from the random
control is a red flag that the experiment is vacuous". That warning is about a
*negative* matching - both returning "nothing fits". It does not apply here,
because both return **finite exact minima**, and it is the agreement of two
measured curves that carries the content. A vacuous design could not produce
`s* = 2` for Thue-Morse and `s* = 10` for Rule 30 from the same harness.

So: on prefixes up to n=48, the Rule 30 center column has essentially maximal
automatic complexity - indistinguishable from random, and far above what any
small DFAO could express. This is evidence against a base-2 automatic-sequence
shortcut for Prize Problem 2.

Scope, stated plainly: n <= 48 is short. This says nothing about shortcuts
outside the DFAO class, nothing about bases other than 2, and nothing about
prefixes beyond 64. It replaces a vacuous claim with a small, honest one.

## Next Step

**To promote to Certificate:** emit DRAT proofs for the UNSAT verdicts. The
SAT side already ships a re-verified witness DFAO, so the *upper* bounds are
certificate-grade today; the *lower* bounds currently rest on trusting CaDiCaL.
With DRAT, `s*(n)` becomes independently checkable and the row can be promoted.

**To extend the curve:** n=56 and n=64 need more than 120 s per instance. Either
raise the timeout, or exploit monotonicity harder - the run already prunes via
"no <k-state DFAO fits the shorter prefix", which collapsed 8 of 10 state levels
to `UNSAT_IMPLIED` at n=32 for free.

**Do not** simply push n higher at fixed state budget. That makes the negative
*more* vacuous, not less, which is the mistake the counting bound exists to
prevent.
